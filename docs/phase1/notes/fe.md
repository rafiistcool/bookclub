# FE (#48) implementation notes

Owner: FE. These notes record what the frontend package built, where it fills gaps the design left open or deviates from it, the new user-visible strings, and what the integrator and the later FE parts need to know. The design documents themselves are unchanged.

## Status

#48 is built in three parts. **Part 1: the foundation and the personal pages on the new server.**

- **Build and dev setup.** `vite.config.ts` builds into `frontend/dist` and proxies `/api` **and `/media`** to `127.0.0.1:8080` (covers and avatars are `/media/…` URLs the server answers).
- **API client** (`src/api/client.ts`):
  - `requestHeaders()` is the one place request headers are built (the apps' bearer token goes there in Phase 4).
  - Global 401 handling: `setUnauthorizedHandler()`; `src/sessionExpiry.ts` installs a handler (from `router.ts`) that resets the session and replaces the route with `/login?next=<path>`. `safeNextPath` (`src/nextPath.ts`) only lets a single-slash path through: no `//host`, backslash or control character.
  - `ApiError` keeps the whole parsed body (`body`), plus `item` (shelf 409) and `job` (import 409).
  - Every function is typed with `src/api/generated.ts`; paths take numeric work ids, or a legacy key for `book()`.
- **Types.** `src/types.ts` is now only aliases of the generated types (plus client-only unions such as `ThemeId` and `SearchParams`). Every server shape the app used is an alias now, except the physical shelf layout: `physicalShelf.ts` keeps its stricter local `PhysicalShelfLayout` (the generated one marks every field optional, because it is also the request body).
- **Book identity.** `bookPath(book)` → `/book/{id}` is the only way the app links to a book. The route is `/book/:id`. `parseBookParam` (`constants.ts`) tells a numeric id from a legacy key (`OL…W`, `BC…`, `ISBN…`, `GB…`); the book page asks `GET /api/books/works/{legacy}` and then `router.replace`s to `/book/{id}`, keeping the query and the `#entry-` hash. The same replace happens when a numeric id answers with another id (a merged work). The detail is fetched once: the replaced route reuses it.
- **Covers.** `BookCover.vue` takes a `book` (`BookOut`, `SearchHit` or `BookDetailOut` fit; `CoverBook` in `src/covers.ts`) and renders only same-origin paths (`sameOriginPath`). Small sizes take `cover_thumb_url`, the full-width cover `cover_url`, each falling back to the other. A failed load waits `COVER_RETRY_MS` (1.5 s), retries once with a fresh `<img>`, then tries the other size, then shows the cloth binding. The binding colour key is `bookColorKey` (shared with the bookshelf spines). `ReportCoverSheet.vue` posts `{reason, details}` to `/api/media/{cover_public_id}/reports`; the book page shows "Report cover" under a stored cover.
- **Discover:** search, browse (trending and the five subject rows, as the server still offers them), search history, and the DNB new-releases row (below). Pages after the first are deduped by work id; `on_shelf` is a boolean on hits, so tiles show a generic "Shelved" badge; the "Club" badge means `club_picks` is not empty.
- **Book page** (`BookDetailOut`): status, progress, rating with an "only me" checkbox (`rating_visibility`), take, DNF reason, favourite, remove with undo (it re-adds with `work_id`, the edition, the rating visibility and the notes), "Refresh details" when `can_refresh`, "View on Open Library" for OL works, "Added by a reader" for user-added works, readers linking to `/u/:username`, the diary (`BookDiary` now takes a numeric `workId`), and the club actions (below).
- **Add your own book** (`AddBookSheet`): optional ISBN; a 409 `That ISBN is already in the catalog` offers "Open that book" (`work_id` from the body). The answer's `id` is the new book's page.
- **Shelf, physical shelf, favourites:** the new shapes (`ShelfItemOut` with `edition` and `rating_visibility`; favourites by `work_ids`). The shelf asks `GET /api/clubs` only when the user has clubs, for the "Club" badges (`clubPickIds`).
- **Other readers' shelves** live at `/u/:username` and `/u/:username/shelf`; `/club/:username[/shelf]` and `/friends/:username` redirect there. A stranger and an unknown name get the same mapped 404 text. The back link goes back in the tab's history (or home when opened directly).
- **Goodreads import** (`components/GoodreadsImport.vue`, `src/goodreads.ts`): the upload answers 202 with a job; the page polls `GET /api/shelf/import/{id}` every 2 s (`pollImport`) and shows progress (`processed / total`), then the summary toast. A 409 adopts the running job from the body. Skips are translated by `code` (`settings.importSkip.*`, the server's English as a fallback), `"Untitled"` is translated. The tab remembers its last job (`sessionStorage["bookclub.import-job"]`), so coming back to Settings shows it again; the job runs on the server either way.
- **Translations.** `src/i18n/apiErrors.ts` maps every detail string of endpoint-map §11.1 and §11.3, the optional catalog strings of §11.3, and the user-visible new strings of the Wave 2 notes (below), with en and de keys. `No profile picture` and `That book is not in the club yet` are gone. Templates are matched by `API_ERROR_PATTERNS` (only `The library is busy. Try again in {n} seconds.`), which the Rust copy test does not scan. `backend/tests/test_api_error_copy.py` is deleted and `LEGACY_ONLY` in `server/tests/api_error_copy.rs` is empty.
- **Tests:** 202 vitest tests in 32 files (158 before). Adapted: every file of spec/frontend.md §4 whose data or paths changed. New files: `covers.test.ts`, `nextPath.test.ts`, `sessionExpiry.test.ts`, `goodreads.test.ts`, `releases.test.ts`, `clubActions.test.ts`, `timezone.test.ts`, `i18n/apiErrors.test.ts`, `components/GoodreadsImport.test.ts`, `components/ReportCoverSheet.test.ts`. `src/test/fixtures.ts` builds complete API objects for tests.

**Part 2: the club context.**

- **`useClubs`** (`src/stores/clubs.ts`). The switcher's list is `UserOut.clubs` (it comes with the session, so it costs no request); `GET /api/clubs` (`loadList`) adds each club's current pick for the cards and is never asked without a club. `upsert` keeps `UserOut.clubs`, the cards and the open club in step with any `ClubOut` the server answers (create, join, transfer, rename); `refresh` re-reads `GET /api/clubs` after a leave or delete. `clear` runs on login, sign-up and logout.
- **Last-used club:** `localStorage["bookclub.club"]`, every access in try/catch. `defaultClubSlug` uses it only while the viewer is still in that club; otherwise the only club; otherwise none. `clubLanding(clubs, last, sub)` is where a club link without a slug leads: `/c/<default><sub>`, else `/clubs`.
- **Routes:** `/c/:slug` (`layouts/ClubLayout.vue`) with the sections `""` (pick), `discussions`, `vote`, `members`, `overlap`, `events` (`pages/club/*`); `/clubs` (the list, and the create-or-join screen); `/clubs/new`; `/join/:code` (public, outside the app shell). `/club` (the Club tab), `/overlap`, `/invites` and `/pick` are `beforeEnter` redirects that run after the session is loaded: `/club` and `/friends` → the default club or `/clubs`; `/overlap` → `…/overlap`; `/invites` → `…/members`; `/pick` → the club, or `/` without a default club.
- **Club layout:** loads `GET /api/clubs/{slug}` (membership check, role, name), remembers the slug, shows the club name, the member count, the viewer's role (admins), the switcher and the section tabs, and renders the section only once the club answered (`useCurrentClub()` in the sections). A 404 `No such club`, from the layout or from any section call (`isClubGone` → `markGone`), shows "Club not found" and drops the slug from storage and from the switcher. Other errors keep the page with a retry.
- **Switcher** (`ClubSwitcher.vue`): a native `<select>` of the viewer's clubs when there are two or more (it keeps the section: `/c/a/vote` → `/c/b/vote`), plus "All clubs" (`/clubs`).
- **Role-aware UI** (`isClubAdmin`/`isClubOwner` on the role string): members see no meeting edit, no "Confirm winner", no deadline, no milestone edit, no invites, no club settings and no member actions; admins also remove plain members and moderate club posts (Delete on others' club posts, from `UserOut.clubs` role of the post's club); the owner also changes roles, hands the club over and deletes it. The server enforces all of it; the UI only hides.
- **Pick** (`ClubHomePage.vue`, from the old Home): the current pick, the readers, "Start reading" and the progress slider, the **meeting edit through `PATCH /api/clubs/{slug}/pick`** (`{meeting_at}` only; an explicit `null` clears it), an "Add to calendar" link to `…/pick/meeting.ics`, the milestones (`MilestoneList.vue`: list for everyone; add with title, unit, range and due date, and delete for admins), a three-entry preview of the discussion, the next-up leader, and the past picks (each opens its own discussion).
- **Discussion** (`ClubDiscussionsPage.vue`): `BookDiary` with `club: {slug, pickId}` reads `GET …/pick/posts` (or `…/picks/{id}/posts` for `?pick=<id>`) and writes `POST` to the same path; `can_post: false` (an ended pick) hides the composer and the reply buttons; a 404 `No club pick yet` says there is nothing to discuss. Below it, `DiaryFeed` with `club` (`GET /api/diary?club=`): the club's posts and its members' diary entries.
- **Vote** (`ClubVotePage.vue`, `NextUpVote.vue`): nominations, cast, "x of y voted · waiting for …", the deadline (admins set or remove it through `PATCH …/vote`, local time in the club zone), "Confirm winner" (admins, `POST …/vote/apply` with the meeting), which then opens the club's pick; the suggestions (`GET …/vote/suggestions`) with their reasons translated (`src/suggestions.ts`) and a Nominate button.
- **Members** (`ClubMembersPage.vue`): the roster from `GET …/members` (the viewer included, marked), each with role, currently-reading previews and joined day; a "Manage" sheet with Make admin / Make a regular member, Hand over the club and Remove (two taps each for the last two); **invites** for admins (new single-use invite, new link, copy and share the `url`, withdraw, the used and ended ones folded away with their state); **club settings** for admins (name and time zone, `PATCH /api/clubs/{slug}`); **leave** for members and admins (two taps), and for the owner an explanation plus **delete** (type the club's name). After a leave or delete the app goes where `/club` would.
- **Overlap** (`ClubOverlapPage.vue`) and **activity** (`ClubEventsPage.vue`, `ActivityFeed.vue` with `club`).
- **Activity feed** (`ActivityFeed.vue`, `src/activity.ts`): one line per event kind of the schema (16 kinds, plus the reaction without a known author and the auto-closed vote), with the actor and the book as links (`<i18n-t>` slots), a second line for a finished book's stars and take, a DNF reason, a quote excerpt or the winning votes; times are formatted from `created_at` in the item's club zone, or the viewer's for personal events (`postTimeZone`). An unknown kind shows "actor · book".
- **Home** (`HomePage.vue`): with clubs, the club cards (`ClubCard.vue`: name, member count, role, the current pick and its meeting), "Currently reading" (the viewer's shelf, with progress sliders), the combined diary (`GET /api/diary`) and the combined activity feed (`GET /api/activity`). **Solo mode** (no clubs): no club call at all (no `GET /api/clubs`, no `GET /api/activity`); a "Read together" prompt (create a club, join with a code), "Currently reading", "Your notes" (`GET /api/diary`) and the favourites.
- **Join** (`JoinPage.vue`): previews the code (`GET /api/invites/{code}`). Signed in, one tap on "Join <club>" accepts it (`POST …/accept`), upserts the club, remembers it and opens it; 409 `You are already in this club` goes to the club; other errors show the mapped text. Signed out, the code waits in the tab (`sessionStorage["bookclub.join"]`, `src/invites.ts`) and in the links: "Create an account" → `/register?code=<code>`, "Sign in" → `/login?next=/join/<code>`. The login page's sign-up link carries the code on (`joinCodeFromNext`, or the waiting code); the sign-up form is pre-filled with it and, when the account came with a club, opens that club. A sign-up-only invite says so. The code field on `/clubs` accepts a bare code or a whole invite link (`parseInviteCode`).
- **Create** (`NewClubPage.vue`): name and time zone (the browser's IANA list, `timeZoneOptions`, the viewer's zone first selected) → `POST /api/clubs` → the new club's Members page, to invite people. An unverified account sees why it will be refused (403 `Verify your email address first`, mapped); the limit and name errors show mapped.
- **Diary toggles** (`BookDiary.vue`, `DiaryEntry.vue`): "Only me" in the composer of a work's diary (roots only; replies and club posts never carry `visibility`) and in the edit of an own diary root (`PATCH /api/posts/{id}` with `visibility`); an `only_me` entry shows an "Only you" badge.
- **Translations:** the club area's strings of CLUB notes "Strings" are mapped now too (`No club pick yet` … `No nomination with that id`, and `That milestone is not on this pick`). `aria-label="Main"` is translated (`nav.main`).
- **`legacyApi` is deleted**, and so is `ClubPage.vue` (its sections moved to the club pages; its four feed tests moved to `components/DiaryFeed.test.ts`).
- **Tests:** 280 vitest tests in 46 files (202 before). New files: `stores/clubs.test.ts`, `router.test.ts`, `nav.test.ts`, `activity.test.ts`, `invites.test.ts`, `suggestions.test.ts`, `layouts/ClubLayout.test.ts`, `pages/club/ClubHomePage.test.ts`, `pages/club/ClubMembersPage.test.ts`, `pages/HomePage.test.ts`, `pages/JoinPage.test.ts`, `pages/NewClubPage.test.ts`, `components/NextUpVote.test.ts`, `components/BookDiary.test.ts`; `components/DiaryFeed.test.ts` (from `ClubPage.test.ts`); new cases in `api/client.test.ts`. `src/test/storage.ts` stubs `localStorage`/`sessionStorage` (the test runtime's own needs a backing file).

**Part 2, second commit: quotes, the auth pages and the account settings** (the rest of part 1's list).

- **Quotes** (`components/QuoteList.vue`, `pages/QuotesPage.vue`): `/quotes` lists the viewer's own quotes (`GET /api/quotes?username=<me>`) with their books; the book page gets a Quotes section under the diary (`?work=<id>`: the audience's quotes of that work) with a composer (line, optional page, "Only me"). Own quotes can be edited (line, page, "Only me"; `PATCH /api/quotes/{id}`) and deleted (two taps); an `only_me` quote shows "Only you". The Shelf page links to `/quotes`, and the Shelf tab stays lit there (`nav.ts` `also`).
- **Sign-up** (`pages/SignupPage.vue`, was `RegisterPage.vue`) at `/signup`; `/register` redirects there with its query. `ServiceConfig.signup` `"open"` hides the invite field behind "Have an invite code?" and makes it optional; `"invite"` (also the default before the config answers) shows it as required. The code comes from `?code=` or the waiting invite; the address is trimmed; after sign-up a toast says where the confirmation link went, and a club invite opens that club.
- **Mail links:** `/verify-email` and `/reset-password` are public (a signed-in reader may open them). They read the token from the fragment (`#token=…`, `src/authToken.ts`; `?token=` works too) and drop it from the address bar at once. Verify posts it and refreshes the session's user when signed in; reset asks for the new password, posts it, and forgets this tab's session (the server ended all of them). `/forgot-password` (guests) always answers the same way and says that an account without a confirmed address gets no link. The login page links "Forgot your password?" and notes that the identifier may be the confirmed address.
- **Email prompt** (`components/EmailPrompt.vue`, at the top of every app page): for `needs_email_prompt`, "Add an address" (`PUT /api/auth/me/email` with the current password) or "Not now" (`POST /api/auth/me/email-prompt/dismiss`; the prompt hides at once even if that call fails).

## Decisions and deviations

1. **`legacyApi`** (part 1's stopgap for the single-club paths) is gone: every club call takes the slug (part 2).
2. **Club actions on the book and shelf pages** (`ClubBookActions.vue`, `clubActions.ts`): "Set as club pick" is offered in clubs where the viewer is owner or admin, "Nominate" in every club, both from `UserOut.clubs` (no request). With one eligible club the action goes straight there; with several a sheet asks which. The pick uses `PUT /api/clubs/{slug}/pick` with the club's zone on the meeting field; a club whose pick is already this book is disabled. With no clubs neither button exists (solo mode). They still read `UserOut.clubs`, which `useClubs` keeps current.
3. **`useClub` → `useService`** (`stores/service.ts`): it only holds the branding of `GET /api/config` now (`ServiceConfig` has no `timezone`). Post times use `postTimeZone` (`timezone.ts`): a club post's club zone (from `UserOut.clubs`), else the viewer's `UserOut.timezone`, as posts.md "For FE" asks.
4. **Legacy book keys** are recognised by pattern; anything else that is not a numeric id shows "That book is not in the catalog." without a request.
5. **Diary drafts** are keyed by the numeric work id now (`bookclub.draft.<user>.<id>`). Drafts saved under the old `OL…W` keys are not carried over.
6. **Fallback colours** (cover cloth and bookshelf spine) hash `ol_work_key` for Open Library works, as before, and `work:<id>` for every other work, so all editions of a work look alike. Legacy `BC…`/`ISBN…`/`GB…` books get new fallback colours once.
7. **New releases** (`GET /api/books/new-releases?language=ger`) are shown to readers whose UI language is German ("German users", work-plan catalog 14), as a row after Trending, with "Erscheint am …"/"Erschienen am …" under each tile (`releases.ts`). The row is hidden while the list is empty (it stays empty until the harvester has run), so it never reads as an error.
8. **Settings:** the invite section is removed (invites move to the club page in part 2, and `/api/invites` no longer exists); the database backup link became "Export my data" (`/api/auth/me/export`). The Goodreads import moved into its own component.
9. **Sign-up form:** part 1 added the email field, the browser's time zone and the UI locale to `RegisterPage`; part 2 turned it into `/signup` (`SignupPage.vue`, open or invite mode from `ServiceConfig.signup`), with `/register` redirecting.
10. **401 handling** fires only while a user is signed in, and never for `/api/auth/login` and `/api/auth/tokens` (a wrong password). A guest page (`meta.guest`) is not redirected.
11. **Strings mapped beyond §11** (all exist in `server/src`, the Rust test checks them): `That is not a valid ISBN-10 or ISBN-13`, `Could not look that ISBN up right now. Try again.`, `A title is required`, `Already on your shelf`, `Book not on your shelf`, the three Goodreads parse errors, `The import stopped unexpectedly. Try again.` (a job's `error`, translated the same way), `Percent milestones go up to 100`, `A range needs a unit`, `Replies and club posts cannot be private`. Not mapped (no UI shows them yet): CAT's edit-request templates `Unknown field: <key>` and `Invalid value for <key>`, the admin-only `This request was already decided` and `This report was already resolved`, MED's `Could not load the cover right now. Try again.` (only an `<img>` sees it), and the pydantic enum and pattern messages.
12. **Join needs one tap.** spec/frontend.md §5.1 proposes that `/join/:code` joins as soon as a signed-in reader opens it. It shows the club and a "Join <club>" button instead, so a forwarded or prefetched link never makes anyone a member by itself; after "Sign in" the reader comes back to the same page and taps once.
13. **Old routes:** `/pick` goes to the default club's pick (the pick was the old Home), and to `/` when there is no default club, as §5.1 says. `/club` with several clubs and no last-used one goes to the club list, not to the newest club.
14. **Section paths** are the proposal of §5.1: `/c/:slug` (pick), `/discussions`, `/vote`, `/members` (with invites and the club settings; there is no separate `/c/:slug/settings`), `/overlap`, `/events` (the activity feed). The tabs read Pick, Discussion, Vote, Members, Shared wants, Activity.
15. **Members include the viewer** (`you: true`, dashed card, "That's you"); the old `members.length + 1` count is the roster's length. "Only you here" shows when the roster has one name.
16. **Moderation:** the Delete button appears on another member's club post for admins and the owner of that post's club (endpoint-map §8), in the work's diary as well as in the club discussion. Edit stays the author's.
17. **The vote's "Confirm winner"** opens the club's pick page afterwards, so the new pick is visible at once.
18. **Leave and delete** forget the club locally first (`forget`), then re-read `GET /api/clubs`; when that fails the forget still stands, and the next session load corrects it.
19. **Activity times** come from `created_at` (formatted like every other club time, in the club's zone for club events and the viewer's for personal ones) rather than the English `created_label`, which stays the fallback.
20. **Home for club members** also lists "Currently reading" (one `GET /api/shelf`), which §5.4 only asks for in solo mode; the favourites row stays solo-only, where there is no activity feed beside the diary.
21. **Time zone pickers** (new club, club settings) list `Intl.supportedValuesOf("timeZone")` plus the current value and `UTC`; a browser without that list offers just those.
22. **Settings order:** profile, then the account (address, password, devices, notifications), favourites, language, appearance, import, export, delete account, log out.
23. **Notification preferences** are kept for Phase 4's push (the copy says so); nothing sends them in Phase 1.
24. **Quotes are added on the book page**, where the work is known; `/quotes` lists and edits them. Another reader's quotes show on the book page (their audience) and on no `/u/:username` page yet.
25. **The sign-up toast** names the address the link went to, even when the server sent no link because a verified account holds it (the server does not say, and neither does the page).

## Blocked on frozen interfaces

Nothing blocks. Things the OpenAPI document does not describe, worked around in the client: the extra fields of some error bodies (`item` on the shelf 409, `job` on the import 409, `work_id`/`edition_id` on the ISBN 409) are read from `ApiError.body` by hand, since `ErrorBody` has only `detail`; and `ClubSummary.role`/`ClubOut.role`/`MemberOut.role` are plain strings in the schema, so `clubsFor`, `isClubAdmin` and `isClubOwner` compare against `"owner"`/`"admin"` literals.

Part 2 adds two:
- `ActivityItem.payload` is an object without a schema (`Record<string, never>` in `generated.ts`); `src/activity.ts` reads the per-kind keys (`status`, `rating`, `take`, `reason`, `progress`, `excerpt`, `emoji`, `author`, `title`, `votes`, `auto`) by hand.
- `VoteSuggestionOut.reasons` (`GET /api/clubs/{slug}/vote/suggestions`) are English sentences without a code. `src/suggestions.ts` translates the four shapes `server/src/votes/suggestions.rs` writes by pattern; a reworded reason would show in English. A `code` plus values per reason would make this robust (a server change, not FE's).
